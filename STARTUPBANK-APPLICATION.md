## Part 2: Technical & UX Compliance (MiniPay Gateway Rules)

- [x] **Zero-Click Connect:** Implemented. Address is fetched instantly via `window.ethereum.request({ method: 'eth_accounts' })` when running inside MiniPay WebView. No manual connect button.
- [x] **No Message Signing:** Compliance verified. The app uses the connected wallet address for authentication and state mapping without prompts for `personal_sign` or `eth_signTypedData`.
- [x] **UI Copywriting Rules:** All crypto-jargon has been updated across user flows:
  * "Gas/Gas fee" $\rightarrow$ **Network fee**
  * "Onramp/Buy crypto" $\rightarrow$ **Deposit**
  * "Offramp/Sell crypto" $\rightarrow$ **Withdraw**
  * "Crypto/Token" $\rightarrow$ **Stablecoin** or **Digital dollar**
- [x] **No CELO token:** The app exclusively handles stablecoins (cUSD, USDC, USDT) and abstracts CELO fees.
- [x] **Low-Balance Handling:** Users are cleanly redirected to the MiniPay Cash-In link (`https://link.minipay.xyz/add_cash?tokens=USDm,USDC,USDT`) on transactional failure.
- [x] **Legal Links & Brand:** Terms of Service, Privacy Policy, and visually distinct branding (no overlap with Celo/MiniPay logos) are integrated.

## Part 3: Celo DevRel Requirements

* **CIP-64 Fee Abstraction:** Our transaction payload injection dynamically reads the user's selected stablecoin (cUSD, USDC, or USDT) and correctly attaches the `feeCurrency` parameter to ensure gas abstraction.
* **EIP-1559 Parameters:** Compliant. Hardcoded `maxFeePerGas` and `maxPriorityFeePerGas` overrides are omitted. The app relies on legacy transaction processing parameters as required by MiniPay.
* **Verified Source Code:** All V1 and V2 smart contracts are fully verified on Celoscan, enabling transparent review.
